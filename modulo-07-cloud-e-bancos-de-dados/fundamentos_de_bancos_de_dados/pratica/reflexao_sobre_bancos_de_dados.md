# Reflexão sobre fundamentos de bancos de dados

Este conteúdo me ajudou a conectar conceitos teóricos com atividades que já realizei usando SQL, SQLite e DBeaver.

Ao explorar um banco com várias tabelas, percebi que conhecer somente a sintaxe de uma consulta não é suficiente. Antes de escrever um `SELECT`, é importante entender a estrutura do banco, identificar chaves primárias e estrangeiras, observar os tipos de dados e descobrir como as tabelas se relacionam.

Também passei a compreender melhor por que:

- constraints ajudam a preservar a qualidade dos dados;
- índices podem acelerar buscas, mas possuem custos;
- transações precisam garantir as propriedades ACID;
- bancos transacionais e Data Warehouses atendem a necessidades diferentes;
- um bom modelo facilita consultas e reduz inconsistências.

Na prática, quero continuar desenvolvendo o hábito de inspecionar o esquema antes de consultar os dados, validar os resultados e registrar as decisões tomadas durante a análise. Assim, SQL deixa de ser apenas uma sequência de comandos e passa a fazer parte de uma compreensão mais completa sobre armazenamento, integridade e uso dos dados.

Esta reflexão é autoral e representa o que compreendi ao revisar o conteúdo estudado.
